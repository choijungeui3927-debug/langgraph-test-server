| 저장소 | `choijungeui3927-debug/langgraph-test-server` |

| 대상 채널 | 한국경제TV, 삼프로TV, 증시각도기TV (10/1 변경, 이전: 매일경제TV 포함) |

## 2026-09-30 (1일차) — 수집·요약 파이프라인과 채팅

### 목표
- 뉴스 채널 목록을 정해 두고, 그날 올라온 영상을 자동으로 가져와 요약한다.
- 범위: 한국어 금융·경제 뉴스, OpenAI 사용
- 메시지 전송과 매일 자동 실행은 나중에 구현한다.

### 한 일
1. **그래프 설계와 구현**
   - 흐름: `fetch_videos → summarize_video(병렬) → write_digest`
   - 영상별 요약을 병렬로 실행한 뒤 주제별 브리핑으로 합친다.
2. **영상 목록 수집**
   - YouTube RSS 피드가 404만 반환해서 **yt-dlp**로 채널 '동영상' 탭을 읽도록 바꿨다.
3. **자막 수집**
   - `youtube-transcript-api`로 한국어 자동 생성 자막을 받는다.
4. **채팅 기능**
   - 브리핑 결과를 날짜별로 `data/날짜.json`에 저장한다.
   - `chat` 그래프를 추가했다. 브리핑을 보고, 자세한 질문은 자막 원문을 검색·조회해서 답한다.
5. **실행 환경**
   - LangGraph Studio를 띄울 수 있게 했다.
   - 더블클릭으로 실행하는 `digest.bat`(브리핑 생성)과 `studio.bat`(채팅 서버)을 추가했다.
6. **정리**
   - README를 작성하고 불필요한 파일을 삭제했다.
   - LangSmith 프로젝트 이름을 `Youtube Finance`로 정했다.

### 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 업로드 시각이 사라짐 | `lang=ko` 옵션을 쓰면 yt-dlp가 한국어 상대 시간("3시간 전")을 해석하지 못함 | 날짜는 영어 조회에서, 한국어 원제목은 `lang=ko` 조회에서 따로 가져옴 |
| 첫 실행 17분, 44개 중 39개 제외 | 자막 요청이 많아 YouTube가 이 PC의 IP를 차단(`IpBlocked`) | 자막 캐시 추가, 제외 사유 구분, 요약 영상 수 제한(10개 → 이후 5개) |
| IP 차단 우회 실패 | yt-dlp 자막 `429`, 브라우저 흉내(`curl_cffi`)도 무효, 오디오 `403`, 설명란은 광고 위주 | 무료 우회 수단 없음을 확인 |
| Apify 프록시 사용 불가 | 무료 플랜은 프록시 외부 접근 기능이 꺼져 있음 | Apify 자막 Actor(`pintostudio/youtube-transcript-scraper`)로 대체. 영상당 약 $0.01 |
| 뉴스 영상 절반이 제외됨 | LLM의 '뉴스성 판정'이 시황 분석 방송까지 걸러냄 | 판정 필터 제거 (채널을 이미 경제 방송으로 골라 둠) |
| Studio 실행 실패 | `.env` 한글 주석과 패키지 파일을 cp949로 읽음, Windows용 `colorama` 없음 | `.env` 주석 영문화, `colorama` 추가, `PYTHONUTF8=1`로 실행 |
| Studio "Failed to fetch" | 로컬 서버가 꺼진 상태에서 접속 | 서버를 켜 둔 채 접속하도록 `studio.bat` 제공 |

### 결정
- **비용 원칙**: 무료 경로를 우선한다.
  - 자막은 캐시 → 무료 직접 요청 → Apify 순으로 시도한다.
  - Apify는 월 예산 $4를 넘으면 호출하지 않는다(무료 플랜 한도 $5).
- **NotebookLM은 쓰지 않는다**: 공식 API가 없고, 비공식 도구는 계정 제재와 동작 중단 위험이 있다.
- **서버는 필요할 때만 켠다**: 채팅할 때만 Studio 서버를 켠다.

## 2026-10-01 (2일차) — 영상 선별 기준과 숫자 레이어

### 목표
- 브리핑에 쓸 영상을 고르는 기준을 개선한다.
- 브리핑의 숫자(지수, 수급, 환율, 종목 등락률)를 LLM이 아니라 코드가 확정하게 한다.

### 한 일
1. **마감 방송 우선 선별**
   - 선택 순서: 한국장 마감 1개 → 미국장 마감 1개 → 나머지 마감 → 일반 영상
   - 한국장은 당일 15:30(KST)에 끝나고, 미국장은 다음 날 새벽(KST)에 끝난다. 그래서 그날 오전에 올라온 미국 증시 영상은 **미국 현지 전날 장**을 다룬다.
   - 미국장 마감 방송은 제목에 '마감'이 없는 경우가 많아, 오전 업로드와 미국 증시 키워드(뉴욕증시, 월가, 나스닥 등)로도 판별한다.
2. **업로드 날짜 버그 수정**
   - 하루 이상 지난 영상은 목록에 "1 day ago"로만 표시되어 날짜가 하루까지 틀렸다.
   - 해당 영상만 영상 페이지에서 정확한 업로드 시각을 다시 받는다.
3. **읽기용 브리핑 파일**
   - `data/날짜.md`를 함께 저장한다.
   - 내용은 브리핑 전문과 사용한 영상 목록(마감 구분 포함)이다.
4. **숫자 레이어 (`src/facts.py`)**
   - 데이터 소스
     - 지수, 투자자별 순매수, 종목 시세: KRX (`pykrx`). KRX 계정으로 로그인해야 한다.
     - 원/달러: 한국은행 ECOS `731Y001 / 0000001` (원/미국달러 매매기준율). 코드가 맞는지 확인했다.
   - 흐름: `fetch_videos → collect_facts → summarize_video → write_digest`
   - 자막에서 언급된 상장 종목을 코드로 추출해 등락률을 조회한다.
   - 브리핑 맨 위 '오늘의 숫자' 섹션은 코드가 생성한다.
   - 브리핑을 쓴 뒤 `verify()`로 숫자를 검사한다. 오류가 있으면 1회 재생성하고, 그래도 남으면 `logs/fact_check.log`에 기록한다.
5. **9/30 브리핑 생성 및 재생성**
6. **9/29 브리핑 재생성** — 새 선별 기준과 숫자 레이어를 적용했다. 이 과정에서 검증기 오탐을 발견해 고쳤다.

### 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| pykrx 대부분의 함수 실패 | KRX가 데이터 조회에 로그인을 요구 | `.env`에 `KRX_ID`·`KRX_PW` 설정 후 정상 동작 확인 |

## 2026-10-01 (2일차 오후) — 채팅 중심 구조로 전환

### 목표
- 이 서비스의 핵심은 요약이 아니라 **영상 스크립트를 근거로 한 채팅 상담**이다. 스크립트를 정확하고 빠짐없이 저장하고, 채팅이 원문 근거와 타임스탬프를 함께 제시하게 한다.
- 토큰 비용을 고려해 영상 수는 적게 유지한다.

### 한 일
1. **영상 선정 기준 개선**
   - 기존: 마감 방송 규칙 + 채널 순환 최신순. 남은 자리가 시황과 무관한 '가장 늦게 올라온 영상'으로 채워졌다.
   - 1차 변경 (규칙 + LLM): 한국장·미국장 마감은 규칙으로 확보하고, 남은 자리는 `gpt-5.4-mini`가 후보 제목을 보고 골랐다. 고른 이유는 브리핑 파일에 남긴다.
   - 2차 변경 (채널당 1개): 매일경제TV를 빼고 **증시각도기TV**(`@koreanstockrider`)를 추가했다. 채널마다 정확히 1개씩, 모두 3개를 고른다.
     - 후보가 하나뿐인 채널은 그 영상을 쓴다.
     - 후보가 여러 개인 채널들은 LLM이 한 번에 보고 채널마다 1개씩 고른다.
     - LLM이 실패하면 한국장 마감 → 미국장 마감 → 최신 영상 순서로 고른다.
   - 마감 키워드에 `클로징`, `한국시황`을 추가했다.
   - 영상 길이는 **2시간 이내**만 후보로 삼는다. 장 마감 생방송이 길기 때문이다.
2. **스크립트 저장 정비**
   - 저장 위치를 `.cache/transcripts/`에서 `data/transcripts/`로 옮겼다. 이름이 '캐시'라서 지워도 되는 파일처럼 보였다.
   - 저장된 자막 25개를 점검했다. 1분당 400~550자로 고르고, 모두 마무리 인사로 끝나서 **중간에 끊긴 파일은 없었다.**
   - 타임스탬프 구간 목록(`.json`)과 이어 붙인 텍스트(`.txt`)를 함께 저장한다.
   - 파일 이름을 `날짜_채널명_제목요약_영상ID`로 바꿨다. 한국어 파일 이름도 문제없었다.
3. **벡터 검색 채팅**
   - `index_transcripts` 단계: 자막 구간을 90초·600자 이내 청크로 묶고, 로컬 임베딩 **bge-m3**로 **ChromaDB**(`data/chroma/`)에 저장한다.
   - `chat` 그래프를 `classify → retrieve → answer`로 바꿨다.
     - 전체 요약 질문은 브리핑 JSON을 근거로 답한다.
     - 세부 질문은 검색된 청크를 근거로 답한다.
   - 답변에는 `[영상 제목 (분:초)](https://youtu.be/ID?t=초)` 형식의 타임스탬프 링크를 단다.
   - 이미 만든 날짜만 색인하는 `python -m src.index`를 추가했다.
   - 브리핑을 다시 만들면, 그날 선정되지 않은 영상의 청크를 지운다.
4. **실행 진행 로그**
   - 브리핑 실행이 1~2분 동안 아무것도 출력하지 않아 멈춘 것처럼 보였다.
   - 단계마다 `[시각] 1/5 …` 형식으로 진행 상황을 출력한다.
5. **9/30 브리핑 재생성과 자막 정리**
   - 채널당 1개 기준으로 9/30을 다시 만들었다. 한국경제TV 장 마감, 삼프로TV 월가 뉴스레터, 증시각도기TV 한국시황 3개이고, 숫자 검증 오류는 0건이었다.

### 결정
- **영상 수**: 채널당 1개, 하루 3개. 토큰 비용과 채팅 근거의 범위를 함께 고려했다.

## 2026-10-01 (2일차 저녁) — 긴 영상 요약 방식 실험과 적용

### 배경
- 영상별 요약은 자막 앞 2만 자(약 40분)만 사용해서, 긴 장 마감 방송의 후반부가 브리핑에서 빠졌다.
- 한도만 7만 자로 올릴지(A안), 구간별로 나눠 요약할지(B안)를 실험으로 비교했다.

### 실험 (`experiments/compare_summary.py`, 결과 `data/experiments/compare_summary.json`)
- A안: 자막 전체(최대 7만 자)를 한 번에 요약
- B안: 타임스탬프 기준 약 1만 2천 자 구간별 요약 → 합치기 ("같은 주장은 한 번만, 구간 시작 시각 표기")
- 대상: 9/30 삼프로TV 영상 2개. 2만 자 넘는 9/30 영상이 1개뿐이라, 지웠던 마감시황 자막을 실험 폴더에 다시 받았다(약 $0.01).
- 후반부 반영 판정: 핵심 항목마다 bge-m3로 자막 속 가장 비슷한 위치를 찾고, 2만 자 이후면 후반부로 셌다. 자동 판정이라 근사치다.

| 영상 | 원문 | 안 | 호출 | 입력 토큰 | 출력 토큰 | 시간 | 후반부 핵심 |
|---|---|---|---|---|---|---|---|
| 월가 뉴스레터 (43분) | 22,018자 | A | 1 | 13,087 | 816 | 7.8초 | 0/8 |
| | | B | 3 | 15,310 | 2,158 | 11.2초 | 0/11 |
| 9월 30일 마감시황 (71분) | 35,842자 | A | 1 | 21,144 | 700 | 4.6초 | **0/8** |
| | | B | 4 | 24,251 | 2,462 | 7.5초 | **3/8** |

- A안은 전체 자막을 받고도 **앞부분에 치우쳐** 후반부(44%)를 하나도 담지 않았다. 코스피를 "2,838"로 잘못 적은 오류도 있었다.
- B안은 47분 이후 구간의 2차전지·알래스카 LNG·전고체 배터리 내용을 담았다. 입력 토큰은 약 15% 늘었고, 출력은 약 3배, 시간은 약 1.5배다.

### 적용 (`nodes.py:summarize_video`)
- 자막이 2만 자 이하면 한 번에 요약한다 (`SINGLE_PASS_MAX_CHARS = 20_000`).
- 2만 자를 넘으면 구간별 요약 → 합치기(`_summarize_by_sections`, `_MERGE_PROMPT`)를 쓴다. 구간 요약은 병렬로 실행한다.
- **구간은 균등 분할한다** (`_sections`). 사용자 요청으로 1만 2천 자 고정을 바꿨다.
  - 구간 수 = `ceil(글자 수 ÷ 20,000)`, 구간 크기 = 글자 수 ÷ 구간 수
  - 경계는 자막 구간 경계(타임스탬프)에 맞춘다.
  - 예시: 22,018자 → 11,000 / 11,017자, 35,842자 → 17,925 / 17,916자, 45,000자 → 약 15,000자 × 3
- 앞부분만 잘라 쓰던 `MAX_TRANSCRIPT_CHARS`를 없앴다. 이제 요약에 자막 전체가 반영된다.
- 테스트: 22,018자 영상을 구간 요약으로 처리해 핵심 10개에 모두 `[분:초]`가 붙었다(1만 2천 자 고정일 때). 12,660자 영상은 한 번에 요약했다. 균등 분할은 LLM 호출 없이 구간 크기만 확인했다.

### 남은 과제
- 균등 분할로 구간이 커지면(최대 2만 자) 한 구간 안에서 다시 앞부분에 치우칠 수 있다. 실제 요약으로 후반부 반영을 다시 확인해야 한다.
- 구간 요약을 합치면 핵심이 스키마 안내(3~6개)보다 많아질 수 있다(테스트에서 10개).
- 핵심에 붙는 시각은 **구간 시작 시각**이라 정확한 발언 시각이 아니다.
- 9/30 브리핑은 이 방식을 적용하기 전에 만들었다. 다시 만들면 월가 뉴스레터의 후반부가 반영된다.
